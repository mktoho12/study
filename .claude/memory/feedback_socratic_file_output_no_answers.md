Socratic 中にユーザーから「ファイルに出力して」「数式が読めないから書いて」と要求されたとき、書く範囲を絞る：

**書いてよい**：説明、定義、定理、公式、一般的なルール、図表（一般論）

**書いてはいけない**：演習問題の選択肢への当てはめ、各選択肢の評価、最終的な答え、表に「✓/✗」を埋めた完成形

**Why:** Socratic スタイルでは答えを直接教えない・認知負荷はユーザー側に置くのが原則（CLAUDE.md）。ファイル出力はあくまで「数式の表記を読みやすく届ける」ための手段であって、答えそのものを書き下す場ではない。実際 Ch01 §6 確認テストで、ゼロ関数のルールを説明する際に4選択肢への当てはめを表で完成形として書いてしまい、ユーザーが自分で考える機会を奪った。

**How to apply:**
- ファイル出力は「ルールまで」と意識する。応用例を書きたくなっても、選択肢に当てはめた具体結果は書かない
- 表を書く場合、ヘッダー行と選択肢の名前だけ並べて、判定欄は「?」のまま残す
- ユーザーが自分で答えを書き込めるテンプレートとして提供する
- これは Socratic 進行中の話。ユーザーが既に答えを言った後の整理や、Socratic を解除して説明モードに切り替えた場面では適用外
